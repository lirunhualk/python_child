# Python 小学生课件编写规范

## 基本原则

- 一个课件一个 notebook，一个 notebook 可以包含多节课。
- 每节课建议 35 到 45 分钟，围绕一个清晰目标展开。
- 每节课都要能独立验证：学生运行代码后能马上看到结果。
- 少讲抽象定义，多通过“改一改、猜一猜、跑一跑”理解概念。

## 推荐结构

每个 notebook 建议按下面结构组织：

1. 课件标题和适用对象。
2. 学习准备：需要的软件、是否需要素材文件。
3. 第 1 课、第 2 课、第 3 课……
4. 每节课内部包含：
   - 本节目标
   - 老师演示
   - 学生试一试
   - 小挑战
   - 本节回顾
5. 结尾放一个综合小项目。

## Notebook 单元格约定

- Markdown 单元格用于说明、目标、任务和回顾。
- Code 单元格用于可运行的短代码。
- 学生要修改的代码单元格，用注释标出可修改位置。
- 不在 notebook 中保存大量运行输出，避免文件变大和 diff 难读。
- 如果需要图片或数据，放到 `assets/<notebook-name>/`，并使用相对路径引用。

## 难度控制

- 一节课只引入一个主要新概念。
- 第一次出现概念时给出完整代码，第二次再让学生补一小块。
- 避免一开始就讲复杂术语，例如对象、模块、异常、递归。
- 优先使用 Python 标准库；确实需要第三方库时，在 README 或课件开头写清楚安装方式。

## 命名约定

- notebook 文件名使用序号加英文短名，例如 `01_python_first_steps.ipynb`。
- 素材目录与 notebook 主名一致，例如 `assets/01_python_first_steps/`。
- 标题可以使用中文，文件名保持稳定，便于链接和版本管理。

## 维护检查

新增或修改课件后，至少检查：

- notebook 能被 Jupyter 正常打开。
- 代码单元格从上到下运行不会依赖隐藏状态。
- 练习题有明确目标，不需要学生猜老师意图。
- 面向学生的文字简短、明确、友好。
